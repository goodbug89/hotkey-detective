Вы нажимаете ⇧⌘4 — и ничего не происходит. Какое-то приложение забрало сочетание, но какое? В macOS нет API, который бы это подсказал, и в Системных настройках тоже не посмотреть.

HotkeyDetective собирает свидетельства, выносит вердикт и показывает ход рассуждений:

## Как это работает

Единого достоверного источника о том, «кому принадлежит сочетание», не существует, поэтому приложение собирает независимые сигналы и взвешивает их:

| Источник | Что доказывает | Сила |
| --- | --- | --- |
| **Системные сочетания** | Собственная таблица macOS закрепляет это сочетание | Достоверно |
| **Настройки приложения** | Файл настроек известного приложения закрепляет это сочетание | Высокая (низкая, если приложение не запущено) |
| **Сканирование настроек** | Настройки приложения совпадают с известным форматом хранения | Средняя |
| **Реакция** | Сразу после нажатия приложение открыло окно или вышло на передний план | Высокая |
| **Проба горячей клавиши** | Некий процесс удерживает регистрацию Carbon-хоткея | Только наблюдение |

Вердикт бывает `подтверждено`, `вероятно`, `спорно`, `занято, но не опознано` или `свободно`. Каждое утверждение показывает свидетельства, на которых оно основано, — вы судите сами, а не доверяете чёрному ящику.

Важно одно различие: **реакция** доказывает, что приложение *получило* клавишу, а не что оно её *зарегистрировало*. Реакция может подтвердить владельца, но никогда не может его оспорить. Без этого правила ⌘Space выглядело бы как «система и Spotlight конфликтуют», хотя всё в порядке.

## Установка

Требуется macOS 14 или новее.

**Homebrew** (рекомендуется — `brew upgrade` поддерживает актуальную версию):

```bash
brew install --cask goodbug89/tap/hotkey-detective
```

**Прямая загрузка:** скачайте нотаризованный `.dmg` из [последнего релиза](https://github.com/goodbug89/hotkey-detective/releases/latest), откройте и перетащите приложение в «Программы».

**Из исходников:**

```bash
git clone https://github.com/goodbug89/hotkey-detective.git
cd hotkey-detective
Scripts/bundle.sh
open build/HotkeyDetective.app
```

Сборка подписывается сертификатом Developer ID, если он есть в связке ключей, иначе — ad-hoc. Ad-hoc сборки теряют разрешения при каждой пересборке — см. [BUILDING.md](../../BUILDING.md).

## Разрешения

Для зондирования нужны **Универсальный доступ** и **Мониторинг ввода**. macOS требует оба для клавиатурного event tap в режиме только прослушивания.

Нажатия наблюдаются, но никогда не перехватываются, не записываются и не сохраняются. Tap создаётся с `.listenOnly`, поэтому настоящий владелец по-прежнему получает клавишу — именно на этом и построено определение реакции. После зондирования остаётся только то сочетание, которое вы запросили. Сетевого кода в этом репозитории нет.

Без разрешений приложение работает в **ограниченном режиме**: выберите сочетание вручную, и ответ будет получен только из файлов настроек.

## Известные ограничения

- **Проба Carbon-хоткея не видит другие процессы.** `RegisterEventHotKey` сообщает о конфликте только внутри своего процесса, поэтому вердикт «занято, но не опознано» практически недостижим. Приложение, которое регистрирует хоткей, не показывает окон и хранит настройки в неизвестном формате, остаётся невидимым.
- **Названия системных функций на английском, кроме корейского.** macOS хранит собственные переводы там, где мы их прочитать не можем, а свои переводы расходились бы с тем, что вы видите в Системных настройках.
- **Сканирование настроек распознаёт два формата хранения** (библиотека `KeyboardShortcuts` и словари в стиле `MASShortcut`). Приложениям с собственным форматом нужен отдельный парсер — [вклад приветствуется](../../CONTRIBUTING.md).
